# **全自动低风险圣遗物扫描优化需求文档 (PRD)**

**关联项目**：圣遗物管理大师 · 星穹典藏 (Artifact Master)（参见 [README.md](https://drive.google.com/file/d/1HVfWplbuc7Tu_G4Si6oZOETSvi-K6WA9/view?usp=drivesdk)）  
**文档日期**：2026-11-12  
目标版本：扫描器轻量化与全自动流式重构（不直接集成第三方 GPL 源码）

# **1\. 背景与痛点**

当前项目的圣遗物采集功能在工程上实现了极高的人工控制边界，但在真实玩家使用场景下存在**人工操作过重**与**状态校验过脆**两大问题：

* **人工操作断点过多**：当前扫描仅限当前页，每扫完一页（最多 32 件）即停止，需用户手动切回游戏滚轮翻页并点击继续；后台队列存在 20/60 槽上限，满槽即暂停；所有识别结果即便 100% 通过数值校验，也必须人工逐批点确认才能入库。  
* **整页像素哈希导致误中断**：根据 [2026-11-10 交接诊断报告](https://drive.google.com/file/d/1F5T9tpd6Jeika5Hf9q8qWnbWjYm7Va12/view?usp=drivesdk)，[PageScanInput.ps1](https://drive.google.com/file/d/1ZOuABlgrFCBmjiNsnKSGrMoJ6nOaYDMR/view?usp=drivesdk) 在每次点击前后都会对整页最多 32 个格位重新计算像素外观哈希；游戏内任意一格因选中光圈、悬停放大或光效产生的微小变化，都会导致整页签名变化并中断扫描。  
* **二次抓图与通用 OCR 耗时高**：[pageScanStability.ts](https://drive.google.com/file/d/1ncRY8DgVP4mI1uFilC3n4cj_lB69jaiy/view?usp=drivesdk) 确认稳定后，[pageScanBridge.ts](https://drive.google.com/file/d/1qg_PFUxCrrV2EPEnA4mlceCzeTjLWnbA/view?usp=drivesdk) 的 `freeze` 会再次抓图重检；同时通用 `PP-OCRv5` 路径单件中位耗时约 1.03 秒（参见 [候选版验收记录](https://drive.google.com/file/d/1yItYsZ15HCr7G_OChWwFuQJ7xmRcpgCY/view?usp=drivesdk)），大批量扫描耗时过长。

参考 [wormtql/yas](https://github.com/wormtql/yas) 的全自动流水线思路（以及项目前期的 [借鉴优化设计](https://drive.google.com/file/d/1adpJBbUF4-OixZFcvsTGPqNtjDxG4grC/view?usp=drivesdk)），本需求旨在**不直接引入外部 GPL 代码的前提下，在现有 Electron \+ React \+ 原生截图 \+ PP-OCRv5 架构中独立实现"点一次开始 → 全自动扫完背包 → 仅异常件人工确认"的低风险方案**。

# **2\. 安全边界与防风控原则（核心约束）**

本方案在提升自动化的同时，必须严格守住以下反作弊与系统安全红线，确保模拟行为接近正常玩家操作，将风控风险降至最低：

| 维度 | 必须遵守的约束 | 说明 |
| :---- | :---- | :---- |
| **进程与内存** | 零内存读取、零进程注入、零网络封包拦截 | 仅通过 Windows 标准窗口截图（PrintWindow / GDI）与标准前台输入 API 工作，不触碰游戏进程内存或文件。 |
| **权限隔离** | 严禁自动提权 | 不自动弹出 UAC 或绕过 UIPI；若游戏以管理员权限运行，提示用户自行决定是否以相同权限启动本工具。 |
| **游戏状态保护** | 绝不点击锁定、强化、摧毁或装备按钮 | 仅限点击圣遗物列表格位与向下滚动列表，不修改游戏内任何存档或锁定状态。 |
| **拟人化输入节流** | 点击位置微抖动 \+ 操作间隔随机波动 | 模拟人类点击习惯：在格位安全中心区域内加入 ±3\~6 像素随机偏移，单次点击间隔与滚轮间隔引入合理随机抖动（避免固定毫秒级机械高频连点）。 |
| **即时人工接管** | 窗口失焦、分辨率变化、按鼠标右键立即急停 | 任何异常切窗或用户按下右键/急停快捷键时，在当前动作前立即中止后续一切鼠标和滚轮输入。 |
| **合规声明** | 不作"100% 官方免责"虚假承诺 | 在使用说明中明确标注工具采用纯视觉与标准系统输入，虽无侵入式风险，但仍建议仅在静态背包界面使用，用户自愿开启全自动模式。 |

# **3\. 核心功能需求**

## **3.1 简化页面校验：用"窗口锚点 \+ 局部静态特征"替代 32 格全页哈希**

* **涉及模块**：[PageScanInput.ps1](https://drive.google.com/file/d/1ZOuABlgrFCBmjiNsnKSGrMoJ6nOaYDMR/view?usp=drivesdk)、[pageScanController.ts](https://drive.google.com/file/d/15Pp0NzUzZcYUVACMhqi4y7aEPIycSf1L/view?usp=drivesdk)  
* **需求描述**：  
  * 废除"每次点击前后比对全部 32 格外观哈希"的一票否决机制，避免被悬停放大和选中光圈触发误暂停。  
  * 将校验拆分为两项独立且轻量的检查：  
    1. **窗口有效性与前台锚点**：校验游戏窗口句柄（HWND）、进程 ID（PID）、前台激活状态及客户区物理尺寸未发生变化。  
    2. **防误翻页局部锚点**：仅在不含动画边框的局部静态区域（如滚动条滑块位置或顶部标题栏区域）校验未发生意外滚动。  
  * **取消二次 `freeze` 重抓**：当 [pageScanStability.ts](https://drive.google.com/file/d/1ncRY8DgVP4mI1uFilC3n4cj_lB69jaiy/view?usp=drivesdk) 确认当前格位详情稳定后，直接从该已验证帧裁剪右侧详情 ROI 送入 OCR 队列，不再重复抓图和重算整页。

## **3.2 受控自动滚动翻页（替代人工每页翻页）**

* **涉及模块**：[PageScanInput.ps1](https://drive.google.com/file/d/1ZOuABlgrFCBmjiNsnKSGrMoJ6nOaYDMR/view?usp=drivesdk)、[pageScanIpc.cjs](https://drive.google.com/file/d/1pQg6oSvH6zRJjbkCx89jv4pYVKz7bT8Q/view?usp=drivesdk)、[pageScanController.ts](https://drive.google.com/file/d/15Pp0NzUzZcYUVACMhqi4y7aEPIycSf1L/view?usp=drivesdk)  
* **需求描述**：  
  * 新增开关"扫描完当前页后自动翻页"（用户主动开启，默认或首次使用前给予明确提示）。  
  * 当前可见行扫描完成后，原生层向游戏窗口发送固定步长的鼠标滚轮向下滚动指令（带拟人化微停顿）。  
  * 滚动后比对首行/末行卡片特征与滚动条位置，确认已进入新页（若存在半行重叠则自动去重或按可视完整行推进，不漏格、不重复点击）。  
  * **自动终止条件**：  
    1. 连续两次滚轮后页面首末行卡片及滚动条均无变化（判定已到达背包最底部）。  
    2. 检测到当前格位为非五星圣遗物（由于背包默认按品质降序排列，扫完五星即自动停机；也可提供"仅扫已强化圣遗物"选项，遇到 \+0 自动停）。

## **3.3 流式队列与"高置信度自动入库"**

* **涉及模块**：`captureController.ts`、`usePageScan.ts`、仓库持久化层  
* **需求描述**：  
  * **取消队列上限阻塞**：将现有的 20/60 槽阻塞暂停机制改为"流式消费"。OCR 队列在后台持续处理截图，处理完一件立即释放对应的源图 Blob 内存。  
  * **高置信度自动入库模式**：  
    * 当单件圣遗物所有必需字段（部位、套装、等级、主词条、有效副词条及待激活词条）全部高置信度识别，且**100% 通过现有五星强化档位数值合法性校验**、无冲突且无疑似重复时，自动写入本地仓库。  
    * 为每趟全自动扫描生成独立的**批次 ID（Batch Tag）**，支持用户在扫描结束后"一键撤销/回滚本次扫描入库的所有记录"，兼顾零操作与可反悔性。  
  * **异常件集中兜底**：仅将 OCR 识别失败、数值校验存疑或疑似重复的少数条目保留在"待人工复核"列表（保留原图裁剪，支持重识别或手动微调），不打断前台扫页流程。

## **3.4 OCR 提速：跳过全图检测，启用固定排版 Batch 行识别**

* **涉及模块**：`native-ocr/worker.py`、`recognition_router.py`、`artifactFieldLayout.ts`  
* **需求描述**：  
  * 保留 `PP-OCRv5` 离线引擎与"（待激活）"词条支持，不引入受限第三方模型。  
  * 针对标准背包详情面板的固定坐标布局，直接裁剪出**标题、主词条、4 条副词条、等级、装备角色**共约 7\~8 个行切片。  
  * 完全跳过耗时的文本检测（Det）步骤，将上述切片打包为一个 Batch 送入 `PP-OCRv5` 识别器（Rec）一次性推理；仅在行切片置信度不足或校验冲突时，对单张原图回退一次通用识别。  
  * **性能目标**：将单件端到端识别耗时从当前的约 1.03s 降至 250ms 以内（即 200 件五星圣遗物全自动扫完约 1 分钟左右）。

# **4\. 交互流程设计（优化后）**

1. **准备**：玩家打开《原神》圣遗物背包（拉到最顶），切到本工具点击\*\*"一键全自动扫描背包"\*\*，切回游戏窗口。  
2. **启动**：工具检测到原神窗口回到前台且画面静止约 0.5 秒后，自动开始逐格点击并截取右侧详情，过程发出轻柔提示音或静默完成。  
3. **翻页与流转**：扫完当前可见格位后自动滚轮翻至下一页继续；后台同步识别并自动入库高置信度圣遗物。  
4. **结束与收尾**：到达底部或非五星区域后自动停止并发出完成提示音；玩家切回工具即可看到"本次新增 X 件（支持一键撤回）"，若有少数识别存疑的条目，集中核对确认即可。

# **5\. 分阶段实施与验收标准**

| 阶段 | 核心交付 | 验收门槛 |
| :---- | :---- | :---- |
| **P1：去噪与流式** | 移除 32 格全页哈希与二次 `freeze`；实现高置信度自动入库与批次撤回；解除 20 槽阻塞暂停。 | 当前页 32/32 连续三次实机扫描无悬停误中断；人工点击确认次数降至仅异常件。 |
| **P2：自动翻页与防风控** | 实现受控滚轮翻页、到底/非五星自动停机、拟人化点击微抖动与随机节流、失焦/右键急停。 | 连续跨 5 页以上（150+ 件）实机扫描无漏格、无错位、不点击锁定/强化按钮，右键急停响应流畅。 |
| **P3：Batch 行识别提速** | 固定布局行切片 \+ `PP-OCRv5` Batch 识别，保留"待激活"与数值防伪校验。 | 单件中位识别耗时 ≤ 250ms，固定回归样本全字段正确率不低于现有通用基线，负例误接受为 0。 |
