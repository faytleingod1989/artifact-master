# **1\. 核心状态机定义**

将原有的"单页暂停式状态机"升级为支持流式翻页的连续状态机，共有 7 个核心状态：

| 状态 | 触发进入条件 | 允许执行的操作 | 退出 / 流转条件 |
| :---- | :---- | :---- | :---- |
| `idle` | 初始状态或用户点击"结束并清空状态" | 切换配置开关、点击"一键全自动扫描" | 点击开始 → `armed` |
| `armed` | 用户点击"一键全自动扫描" | 轮询检测原神窗口句柄（HWND）与前台激活状态（超时 30s） | 窗口在前台且画面静止 0.5s → `scanning`；超时或手动取消 → `idle` |
| `scanning` | 窗口锚点已锁定，开始逐格采集 | 逐格拟人化偏移点击 → 移开鼠标 → 等待详情稳定 → 裁取右侧详情 ROI 入队 OCR | 当前页完整行扫完 → `scrolling`（若开启自动翻页）或 `completed`（未开启）；遇到非五星或用户设定的 \+0 停止条件 → `completed`；失焦/右键/异常 → `paused` 或 `emergency_stopped` |
| `scrolling` | 当前页完整可见行扫描完成 | 发送固定步长滚轮向下指令，等待画面动画稳定（300\~500ms）并比对局部滚动特征 | 检测到新行进入视口 → 计算重叠行偏移后回到 `scanning`；连续 2 次滚轮画面未变（已到底） → `completed` |
| `paused` | 窗口失焦、分辨率/位置改变、或用户点击"暂停" | 立即停止所有鼠标/滚轮输入；后台 OCR 继续消化已入队截图；恢复 F8 快捷键 | 用户切回游戏点击"继续扫描"（仅当窗口尺寸一致且未手动翻页）→ 重新锚定并进入 `scanning`；用户点击"结束" → `completed` |
| `emergency_stopped` | 用户在扫描中按下**鼠标右键**或急停快捷键 | 毫秒级硬中止原生输入线程，清空待发送点击队列；后台 OCR 保留已完成部分 | 用户确认退出 → `completed`（保留已扫成果） |
| `completed` | 到达背包底部、扫完五星区域、或用户主动结束 | 播放完成提示音；汇总本次自动入库数、待人工复核数与批次 ID；解锁全量界面操作 | 用户处理完待复核项或关闭面板 → `idle` |

# **2\. 关键异常分支与边界处理规则**

开发人员必须按以下明确规则处理所有边缘情况，禁止自行静默跳过或阻塞：

## **2.1 游戏失焦与切窗**

* **规则**：只要检测到 `foreground === false` 或当前前台窗口 HWND 与锁定基线不一致，**必须在当前毫秒内中止下一次点击/滚轮**，立即转入 `paused` 状态，绝不向其他窗口发送输入。  
* **恢复**：不自动抢占游戏焦点。用户在工具内看到"已暂停（游戏失去焦点）"提示，切回游戏或点击"继续"时，重新校验窗口尺寸与局部锚点后才恢复。

## **2.2 滚轮翻页后的行重叠与去重**

* **规则**：由于不同分辨率/DPI 下鼠标滚轮每格滚动的像素高度不同，翻页后可能出现"上一页最底下一行仍留在当前页最顶部"的情况（半行或整行重叠）。  
* **处理方式**：  
  1. 翻页前记录当前页**最后一行完整卡片的图标/等级特征序列**。  
  2. 翻页稳定后，从新视口第一行开始比对：若新视口第 0 行匹配翻页前的末行，则自动跳过第 0 行，从第 1 行继续点击，**既不漏扫，也不重复点击**。  
  3. 底部被视口裁断超过 30% 的半行卡片一律不点击，留待下一次翻页完整露出后再扫。

## **2.3 到达背包底部与四星边界判断**

* **到底判断**：连续发送 2 次向下滚轮指令后，如果滚动条滑块位置与首/末行卡片特征均无变化，判定已到达背包最底部，立即结束并进入 `completed`。  
* **品质/等级停止条件**：当识别到某格卡片边框不再为五星金色（即进入四星紫色区域），或开启了"扫到 \+0 自动停止"且连续遇到两件 \+0 胚子时，立即终止扫描并进入 `completed`（四星不入队）。

## **2.4 单件 OCR 失败、数值存疑或疑似重复**

* **不中断前台扫页**：单件识别失败、出现数值校验冲突（例如小数位无法匹配五星真实强化档位）或命中疑似重复时，**绝不弹窗打断正在进行的前台点击**。  
* **转入待人工复核队列**：将该件的原始详情裁剪图保留在"待人工复核"列表，标记具体原因（如"数值校验存疑""疑似与库存 \#1042 重复""识别超时"），由用户在整趟扫描结束后集中一键处理。  
* **禁止自动删重**：两件属性完全相同的真实五星圣遗物在相邻格位出现时，必须各自独立保留截图任务并正常入库或提示，不得因为"属性和上一件一样"就判定为未切换或自动丢弃。

## **2.5 后台队列积压与内存控制**

* **取消 20/60 件硬性暂停**：只要高置信度识别结果完成自动入库，立即释放该任务的源图 `Blob` 内存，不再触发"队列满暂停"。  
* **极端积压保护**：仅当本机极慢导致"未完成识别的原始截图"堆积超过 80 张（或总内存占用接近 128 MiB 上限）时，才临时进入 `paused` 状态等待后台消化至 40 张以下后自动或提示继续。

## **2.6 原生输入线程安全兜底**

* 任何情况下进入 `paused`、`emergency_stopped` 或 `completed`，前端必须等待原生层明确返回"输入线程已停止"确认后，才允许恢复 `F8` 手动截图快捷键。
