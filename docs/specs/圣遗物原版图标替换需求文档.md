# 圣遗物原版图标替换需求文档

## 1. 文档用途

本文档交给后续开发模型或开发人员执行。目标是修正当前程序的素材规则：角色头像可以继续使用 Q 版或原创头像，但圣遗物图标必须换成《原神》游戏内对应圣遗物的原版图标。

本次不是简单替换五张图片。当前代码只按“生之花、死之羽、时之沙、空之杯、理之冠”五个部位分配通用图片，而原版圣遗物图标由“套装 + 部位”共同决定。实现必须同时调整素材、映射方式、缺图处理和验收测试。

## 2. 当前问题

当前素材位于 `apps/web/src/assets/archive/`，圣遗物默认图标包括：

- `relic-flower-opt.jpg`
- `relic-feather-opt.jpg`
- `relic-sands-opt.jpg`
- `relic-goblet-opt.jpg`
- `relic-crown-opt.jpg`

`apps/web/src/App.tsx` 中的 `slotArtwork` 只根据部位选择图片。因此，不同套装的同一部位会显示同一张非原版图，无法反映圣遗物的真实外观。

角色头像使用 Q 版、原创图或用户自行导入的图片是允许的，不属于本次问题。

### 2.1 已冻结的产品决定

以下决定不再留给执行模型选择：

- 角色头像继续允许 Q 版、原创图和本地导入。
- 圣遗物自定义图标入口本期移除；圣遗物只能显示内置原版图标或明确的缺图占位图。
- 代码改造阶段允许用缺图占位图暴露素材缺口，但最终 Windows 发布包必须达到 20/20 原版图标，不得带缺口发布。
- 内置默认素材全部随安装包提供；用户导入的角色头像存入本地数据层，不属于“随包素材”。
- 原版素材不写入普通用户数据备份，也不需要通过 JSON 迁移，它们跟随应用版本发布。

最终发布的前置输入是 20 张已通过来源审核的原版素材。用户未提供且执行模型也无法取得可确认来源的素材时，只能完成代码改造阶段，并提交缺口清单；不得宣称最终发布完成。

## 3. 目标

完成后应达到以下状态：

1. 程序内每件已支持的圣遗物，默认显示其对应套装、对应部位的原版游戏图标。
2. 不同套装的同一部位必须显示不同图标，不能继续共用通用花、羽、沙、杯、冠图片。
3. 角色头像保持现状，可以使用 Q 版、原创头像或本地导入头像。
4. 所有内置默认图片随桌面程序本地打包，运行时不依赖外部图片链接。
5. 缺少原版图标时显示明确的中性占位状态，不能拿其他套装图标、AI 生成图或 Q 版图冒充。

## 4. 强制素材规则

### 4.1 圣遗物图标

圣遗物图标必须满足以下要求：

- 必须是《原神》游戏中该圣遗物的原版图标，套装和部位都要对应。
- 禁止使用 AI 生成、手绘仿制、Q 版重绘、风格化重绘或当前的通用替代图。
- 禁止把同一部位的一张图复用到所有套装。
- 禁止通过第三方网站图片地址进行运行时热链。
- 图片应保存到项目本地，并经过尺寸与体积优化。
- 不得拉伸、裁掉主体、改变原图比例、套用会明显改变原色的滤镜。
- 如需透明背景，优先使用原始透明 PNG；不应为了统一格式强行转成有底色的 JPG。

### 4.2 角色头像

角色头像不要求使用游戏原版立绘，可以继续使用：

- Q 版头像；
- 原创占位头像；
- 用户在“本地素材”中导入的头像。

角色头像和圣遗物图标是两套独立规则，不要因为替换圣遗物图标而删除角色头像的本地替换功能。

### 4.3 素材来源与合规

- 优先使用用户已经提供、且确认可以在本地程序中使用的原版素材文件。
- 如果需要开发模型自行寻找素材，必须记录来源页面、获取日期和使用依据，先确认可用范围再写入项目。
- 不要从来源不明的图库、网盘或二次创作页面直接复制。
- 本项目如果仅供个人本地使用，也应在素材清单中保留来源记录，方便以后公开发布时统一复核或替换。
- 程序内继续保留“非官方工具，与米哈游/HoYoverse 无隶属关系”的声明。

## 6. 建议的文件结构

建议把素材从 `archive/` 中拆出，按套装组织：

```text
apps/web/src/assets/artifacts/
  manifest.ts
  placeholder-missing.svg
  <set-key>/
    flower.png
    plume.png
    sands.png
    goblet.png
    circlet.png
```

目录名使用稳定的英文或拼音 `set-key`，不要直接依赖中文文件名。中文名称只用于界面显示。

## 7. 数据与代码改造要求

### 7.1 从“按部位”改成“套装 + 部位”

删除或停用当前的单层 `slotArtwork: Record<Slot, string>`。改为显式的套装素材清单，例如：

```ts
type ArtifactSetKey =
  | 'shenlang-zhongqu'
  | 'heiyao-midian'
  | 'zhuying-lieren'
  | 'xishi-zhige'

type ArtifactArtwork = Record<Slot, string>

const artifactArtworkBySet: Record<ArtifactSetKey, ArtifactArtwork> = {
  // 每个套装必须列出五个部位，不允许隐式复用。
}
```

实际实现可以采用独立 `manifest.ts` 或版本化 JSON，但必须满足：

- 类型检查能发现某个套装缺少部位图片；
- 业务数据使用稳定 `setKey`，界面使用中文 `setName`；
- 图标查找函数同时接收套装和部位；
- 找不到映射时返回缺图占位图，并在开发环境输出可定位的警告；
- 不允许自动回退到同部位的其他套装图标。

### 7.2 调整组件参数

`ArtifactGlyph` 不能只接收 `slot`。至少需要接收完整圣遗物或 `setKey + slot`，确保仓库卡片、详情页、强化队列、回收站和推荐方案使用同一套查图逻辑。

所有使用位置都要检查，不能只修仓库首屏：

- 仓库网格卡片；
- 圣遗物详情；
- 强化队列；
- 回收站；
- 推荐方案；
- OCR 待确认与入库后的图标；
- JSON 导入后的图标恢复。

### 7.3 本地自定义图片

角色头像的本地导入功能保留。

圣遗物默认显示原版图标。移除“导入此圣遗物图标”入口以及现有 `artifact:<id>` 自定义覆盖读取逻辑。迁移时不要立刻删除旧覆盖数据：首次升级先忽略这些覆盖并生成迁移报告，用户确认新版正常后再清理孤立数据。

## 8. 图片处理标准

- 推荐源文件：透明 PNG 或来源提供的无损格式。
- 显示区域建议使用正方形画布，主体居中，保留原始比例。
- 单张图片建议控制在 200 KB 以内；若原图较大，可在不明显失真的前提下优化。
- 不要把小图强行放大后再保存，避免模糊和锐化边缘。
- 不要把同一张源图复制成多个不同文件名冒充不同部位。
- `alt` 文本应包含套装名和部位，例如“逐影猎人·理之冠原版图标”。

## 9. 缺图与错误处理

出现以下情况时显示统一缺图占位图，并在界面或开发日志中说明原因：

- 套装没有配置 `setKey`；
- 套装已配置，但该部位没有素材；
- 图片加载失败；
- 本地旧数据迁移后仍无法识别旧套装名称。

禁止采取以下回退：

- 使用当前非原版通用图；
- 使用同部位其他套装的图；
- 临时生成一张相似图片；
- 隐藏错误并显示看似正常的错误图标。

## 10. 验收标准

### 10.1 代码改造阶段验收

- 素材清单完整声明当前四个套装共 20 个“套装 + 部位”组合；暂时缺图的项目显示统一占位图并进入缺口报告。
- 对已配置原版素材的组合，任意选择两个不同套装的同一部位，图标应不同且各自正确。
- 仓库、详情、强化队列、回收站和推荐区域显示一致。
- 新增、编辑、OCR 入库和 JSON 导入后，图标由套装和部位自动决定。
- 修改圣遗物套装或部位后，图标立即更新。
- 缺失映射时显示缺图占位图，不显示错误的原版图。
- 角色头像仍可使用 Q 版或本地导入图片。

### 10.2 最终发布阶段验收

- 20 个组合全部通过素材人工签收，不再存在占位图。
- 每项素材记录 `setKey`、部位、官方中文名、来源地址、获取日期、源文件 SHA-256、项目文件 SHA-256、格式、像素尺寸和文件大小。
- 素材验收负责人在清单中标记通过；未确认来源或对应关系的图片不得进入 Windows 发布包。
- 代码改造通过但素材不足时，只能标为“代码阶段完成”，不能标为最终交付完成。

### 10.3 视觉验收

- 图标主体完整，没有拉伸、裁切或明显失真。
- 桌面端、移动端和 Windows 桌面程序中显示一致。
- 锁定标识、等级和星级不会遮挡图标主体。
- 深色背景下透明边缘没有明显白边或压缩脏边。

### 10.4 工程验收

- `npm run build` 通过。
- `npm run lint` 通过。
- 增加素材清单完整性测试：缺少任意“套装 + 部位”声明时测试失败；声明为 `missing` 的组合允许在代码阶段使用占位图，但会阻止最终发布验收。
- 增加组件测试：有素材的不同套装同一部位得到各自 `src`；缺素材组合得到统一占位图和明确的 `missing` 状态。最终 20/20 素材验收再要求所有组合使用不同且正确的原版 `src`。
- Windows 发布包重新构建，发布包中的素材清单与源码一致。
- 提交素材来源清单，至少包含文件名、对应套装、对应部位、来源和处理说明。

## 11. 明确不做

- 不要求把角色 Q 版头像换成官方立绘。
- 不要求本次增加所有游戏历史套装，只覆盖程序可录入的套装。
- 不使用在线图片接口或热链。
- 不用 AI 生成“看起来像原版”的替代图。
- 不在没有素材来源记录的情况下对外发布含版权素材的安装包。

## 12. 交付物

后续模型完成任务时必须交付：

1. 原版圣遗物素材目录；
2. 套装与五部位映射清单；
3. 素材来源与签收记录，包括源文件和输出文件哈希；
4. 代码修改说明；
5. 自动化测试与运行结果；
6. 桌面端、移动端及 Windows 程序截图；
7. 尚未取得原版素材的缺口列表，不能用替代图掩盖。
