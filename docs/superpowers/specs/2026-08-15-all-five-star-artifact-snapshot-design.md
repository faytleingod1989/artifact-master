# 全量五星圣遗物本地素材快照设计

## 目标

把程序从仅支持 4 套圣遗物扩展为一个固定的“当前五星圣遗物套装”快照：每套 5 个部位均显示本地原版图标，并可在录入、编辑、筛选、OCR 与导入的数据流中正确解析。当前外部目录将五星套装列为 44 套，因此目标规模为 220 个套装-部位组合；实际数量必须由受版本控制的目录文件计算，不得在业务代码中写死 44 或 220。

## 范围与非范围

- 包含：在快照冻结日拥有五星品质的正式《原神》圣遗物套装，每套生之花、死之羽、时之沙、空之杯、理之冠。
- 不包含：仅有 1–4 星品质的套装、非正式内容、AI/重绘素材、角色头像、运行时网络取图。
- 既有 4 套（深廊终曲、黑曜秘典、逐影猎人、昔时之歌）必须保留原有 setKey，确保旧数据不迁移丢失。
- “当前”是一个带来源 URL、抓取日期和游戏版本说明的冻结快照；未来新版本新增套装时，以新的快照批次增量加入，而非自动变更旧发布物。

## 数据架构

新增一个唯一的五星套装目录模块，单项包括：

```ts
type FiveStarArtifactSet = {
  key: string
  name: string
  sourceName: string
  sourceUrl: string
  verifiedAt: string
}
```

目录是以下所有功能的唯一来源：`ArtifactSetKey` 类型、中文名解析、手动录入/编辑/OCR/筛选选项、素材清单、来源登记、发布门禁的预期组合。禁止在 `App.tsx` 再维护四套固定数组。

每项素材路径固定为 `originals/<setKey>/<flower|plume|sands|goblet|circlet>.<png|webp>`。应用通过 `import.meta.glob` 选择本地文件；无文件时始终返回同一中性占位，不会跨套装或跨部位借图。

## 私有素材包与公开源码

原图目录继续被 `.gitignore` 排除。私有 Windows 构建有素材时显示原图；公开源码在没有私有素材包时仍可构建并显示占位。素材登记表必须声明镜像性质、固定提交 URL、获取日期、单件哈希、真实格式、像素、字节数和本地签收。

当前可验证的候选镜像是 GI Loadouts 的提交固定文件；其 README 声明游戏素材权利归 miHoYo/Cognosphere。它是技术来源镜像而非官方授权来源，因此登记表必须如实标为“第三方镜像，仅个人本地使用”，不得表述为官方授权或可公开分发。

## 采集与质量规则

1. 先从五星目录生成预期 `setKey × 5` 清单，再收集文件；不得先下载一批图后倒推名称。
2. 每套素材映射必须由镜像中的套装名称、单件名称和图像三者交叉确认。
3. 下载必须引用固定提交或不可变 URL；文件魔数决定真实 PNG/WebP 格式，扩展名与字节不符时改用真实扩展名，不重新编码。
4. 对每个文件记录源和项目 SHA-256；未裁剪、未改色、保留透明背景与原比例。
5. 逐套抽样查看五部位图像；任一套身份或来源无法确认时，该套保持 `missing`，发布门禁失败。

## 应用行为与兼容性

- 所有套装选择器从目录渲染，支持既有四套和新套装。
- OCR 只对目录中存在的精确中文名生成 `setKey`；未知套装保留原文且显示缺图占位，不猜测映射。
- JSON 导入时仅接受目录所定义的 setKey；当 setKey 与中文名冲突时，以可解析的中文名重新映射，未知值不崩溃。
- 历史数据中无效的部位或套装继续走中性占位与开发警告。

## 发布门禁与验收

发布脚本从目录读取全部预期组合，检查：

- 登记表恰好覆盖每个目录套装的五个部位，无重复或额外组合；
- 每项状态为 `approved`，来源 URL、日期、用途说明、签收字段齐全；
- 本地文件存在，源 SHA-256 和项目 SHA-256 都匹配，格式/像素/字节数匹配登记；
- 所有清单项在应用中为 `ready`，无跨套装回退；
- `desktop:build` 必须先执行发布门禁。

验收命令：`npm run test`、`npm run lint`、`npm run build`、`npm run verify:artifact-release`；只有全部通过时才允许尝试 Windows 便携包构建。

## 风险与处置

- 外部目录与镜像可能落后于当前版本：冻结目录前必须比较至少两个独立的最新套装列表，并把差异写入审计记录。
- 新版本或名称本地化差异：缺少可靠中文名依据的条目不进入 `approved`。
- 私有素材包误公开：`.gitignore`、来源登记的明确警告和发布前文件扫描共同阻止；公开二进制不得携带该目录。
- Windows 打包器环境卡住：不影响素材门禁、测试和 Web 构建结论；需单独排查 Electron Builder 环境，不能复用旧 release 目录冒充新包。
