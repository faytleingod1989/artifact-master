# 圣遗物管理大师：七个独立页面与导航设计

日期：2026-10-05。状态：用户已确认，已按细化计划实施并交付；验证记录见 `docs/superpowers/verification/2026-10-05-page-navigation.md`。

## 1. 目的与确认范围

用户指出顶部导航“没啥用”，原因是仓库、角色、推荐和队列混在一个长页面，点击主要只是滚动。用户已同意保留七个入口，分别做成独立内容页面，不合并“角色配装”和“推荐方案”。

成功标准：点击入口后标题和主体内容真实切换，只显示对应页面；菜单选中项与页面一致。切换不是整窗重载，也不会清空库存、仓库筛选、列表/图标偏好、多选集合或选中角色。保持当前深蓝、米白、暗金风格与游戏原图的完整比例。

本文只重组导航和现有能力的展示，并补齐基于已有本地数据的图鉴页面。不新增完整配装引擎、装备方案持久化、游戏内换装、联网资料更新或云同步。

## 2. 实施前代码依据

- `apps/web/src/App.tsx` 的 `navigateTo` 只更新 `activeNav` 并调用 `scrollIntoView`。角色配装与推荐方案指向同一 `recommendations`；数据图鉴回落到 `inventory`。素材与回收站目前是弹窗。
- `apps/web/src/warehouse/Warehouse.tsx` 把筛选、排序、多选、详情和对比状态放在组件内部。只做卸载/重建会重置这些会话状态，需要明确提升状态归属。
- `apps/web/src/scoring.ts` 提供 `recommendBuild`、`scoreArtifact`、`scoreReason`，属于既有逐部位规则初评。没有完整伤害模拟、队伍循环或实际装备槽管理。
- 本地核实资料来自 `catalog.ts`、`gameData.ts`、`statModel.ts`、`statDefinitions.json` 和原图 manifest；本轮不把这些快照称为当前游戏完整最新版。
- `electron/enkaIpc.cjs`、`electron/captureIpc.cjs` 严格校验主入口 URL。新增 hash 或路径路由会影响 UID/F8 的来源校验，不能为了页面导航放宽安全规则。

## 3. 页面职责

|页面|主要内容与操作|不承诺的能力|
|---|---|---|
|圣遗物仓库|库存筛选、图标/列表、详情/对比、多选、锁定、移入回收站、加入队列；实时录入、手动录入、UID、截图与仓库备份入口|不再把角色、推荐和完整队列堆在仓库下方|
|角色配装|自带 10 个角色头像及现有规则标签；选择角色；五个部位的规则候选和缺失部位；展示已有规则的偏好解释，进入该角色的推荐页面或仓库候选范围|候选不等于游戏内已装备；草案角色不改称权威攻略|
|推荐方案|选中角色的五部位候选详情、单件评分及现有 `scoreReason`、总分与缺失部位；查看仓库对应件、将有效未满级候选加入队列|不生成不存在的多方案、不称实战最优、不更改原评分权重|
|强化队列|最多五件，全部显示；查看词条与已有强化判断，查看对应库存件，单项移除或清空；保留重复/满额反馈|移除与清空只操作队列，不删除库存；不增加自动强化|
|数据图鉴|已核实套装列表与搜索、每套五部位名称和图标；部位合法主词条、0～20 级主词条成长值、已有副词条上下界；标注本地数据版本和素材状态|不编造缺少的套装效果、强化概率或单次强化档位|
|本地素材|10 个内置游戏头像预览、当前自定义头像与原有上传入口；现有 PNG/JPG/WebP 和 3 MB 限制|不恢复单件圣遗物图标覆盖，不自动下载/上传头像|
|回收站|已删除条目、恢复、原有永久清空确认；明确空状态|不增加自动到期删除；没有清理机制就不显示“本地保留30天”|

角色页侧重“选谁、看哪些部位和规则”；推荐页侧重“具体候选是谁、为何推荐、接下来怎么处理”。二者使用同一个角色选择和推荐结果，但主体内容不同。

推荐页标题使用“规则初评候选”，不再使用容易误解的“综合评分最高方案”。偏好解释只说明现有工具规则和草案/稳定标签，不新增或猜测游戏机制。

## 4. 导航与页面容器

采用应用内页面状态，不引入新的路由依赖，不改变 Electron 主入口 URL、hash 或文件路径。用户获得真正的页面切换，但底层仍是同一个本地 React/Electron 应用，导航不触发刷新、联网、重新加载仓库或重新注册 F8。

页面标识固定为 `warehouse`、`characters`、`recommendations`、`queue`、`catalog`、`assets`、`trash`。初次启动、整窗刷新或重开程序默认进入仓库；本轮不新增深链接、浏览器前进后退或页面偏好的持久存储。

- 顶部七个入口共用一份菜单定义，全部可以到达对应页面。
- 现有窄屏导航使用同一份定义，不能只保留前四项导致图鉴、素材或回收站不可达。
- 页面容器只挂载当前主体，不把七页全部隐藏在长页面里。公共导航、保存状态和全局录入弹窗不随主体卸载。
- 点击页面导航后滚动到新页面顶部，并把焦点交给该页标题。选中菜单使用明确视觉状态及 `aria-current="page"`。
- “查看方案”“查看藏品”等跨页操作明确指定目标页面和对象，不再只是滚回同一块内容。
- 加入队列仍留在当前页并给出明确反馈；队列页是查看与管理入口，不因每次加入强制跳页。

## 5. 状态归属与数据流

公共层保留现有库存、回收站、队列、头像、保存状态、保存请求代际及录入会话。各页只通过既有受保护操作修改数据，不新增各自的仓库副本或独立自动保存。

仓库会话状态提升到公共层：视图、筛选、排序、多选 ID、当前详情 ID、对比开关、全部/角色范围。切走时保留，返回时由同一会话状态重建仓库。只有已有视图偏好继续按原键写入本地缓存，其他会话状态不进入 JSON 备份或装备存储。

角色选择也位于公共层，角色页、推荐页及仓库角色范围保持一致。图鉴搜索与选中套装作为独立会话状态保留，不混进库存筛选。

当藏品被删除、恢复或整库替换时，页面只能解析当前库存中确实存在的 ID。已经不存在的详情、多选或对比引用不显示虚假记录、不触发操作；两件对比不足时返回详情或明确空状态。旧本地队列兼容与 v2 导出规则仍沿用本轮优化的既定语义，不借导航改版静默清理用户数据。

从推荐或队列“查看库存件”时，显式跳到仓库并聚焦对应当前记录。若现有筛选/角色范围隐藏该件，显示原因和“清除筛选并查看”操作，不静默改掉原筛选，也不把隐藏条目伪装成筛选结果。

## 6. 录入、保存和错误处理

- 四种来源仍通过现有结构化草稿、疑似重复与确认入库流程。页面切换不绕过校验，也不隐式确认入库。
- 录入/校准/确认弹窗和采集会话保留在公共层。弹窗打开时不接受背后菜单点击；关闭、取消和停止仍按原有明确操作处理，不因主体切换丢弃草稿或停止采集。
- 图鉴仅只读，不改库存或触发素材缓存写入。角色切换不修改装备记录，不触发 UID 查询。
- 保持普通保存的“正在保存/已保存/保存失败”以及“重试保存当前修改”。恢复或确认提交期间，所有页面的修改入口遵守同一 busy/ready 保护。
- 损坏 JSON 仍先整体校验、再原子提交；失败保留原库。备份版本仍为 v2，包含库存、回收站、队列及自定义头像；v1 的清队列兼容不变。
- 自定义图片延期读取完成时只应用到原指定角色键，不能因页面或角色切换应用到另一个角色；现有恢复代际保护继续有效。
- 启动读取失败时仍显示“重试读取”，不得因某页挂载而用默认空库覆盖旧数据。

## 7. 资料与素材规则

图鉴只使用项目现有的已核实五星目录、单件名称、合法词条与成长数据，不从示例文本生成游戏资料。当前基线为 46 套/230 个名称、个人原图 44 套/220 幅；实施时核对基线，如确有其他工作改变数据则按实际记录，不覆盖它。

个人构建可显示已收集原图；缺失项显示清楚的“原图待补”。公开构建不包含这些个人原图或内置游戏头像，应显示“此构建未包含原图/游戏头像”，不暗示目录不存在，也不声称可以联网自动补齐。

所有新页面复用 `ArtifactGlyph` 和 `CharacterPortrait`：`object-fit: contain`、等比居中、禁止拉伸或裁切主体。图鉴大图、列表小图、角色头像、队列图标均按同一规则检查。

副词条上下界明确表示本地校验范围，不表示单次强化数值或概率。没有核实的套装效果标注“效果资料暂未收录”，不显示所有套装共用的假效果文案。

## 8. 模块边界与实施约束

保留 React/Vite/Electron/IndexedDB 和现有用户数据键，不换框架、不升级依赖、不修改 Electron IPC 权限。

拟划分三个职责：公共应用壳负责导航、共享状态和保存；独立页面组件负责各页内容与动作绑定；图鉴只读适配层负责从现有数据模块生成展示内容。仓库状态提升仅为满足切换保留，不扩展为全应用状态库重构。

新页面中禁止复制维护第二份套装名称、词条定义、评分权重或原图映射。角色列表/草案标签可从当前 App 抽到共享配置供两页使用，具体文件和接口在实施计划中明确。

继续使用当前模型在本会话实施，不因为本次拆页恢复旧子代理或擅自换模型。工作区当前不是 Git 仓库，因此文档只保存为本地文件，不初始化 Git 或声称已经提交。
